See [Long decode](/docs/long-decode). * **Supported in Managed Agents:** The [Antigravity agent](/docs/antigravity-agent) in Gemini Managed Agents now supports `gemini-4-carbon`. ## Choosing between Carbon, Argon, and other models {% id=&quot;choosing-between-models&quot; %} Gemini 4 Carbon and [Gemini 4 Argon](/docs/whats-new-gemini-4-argon) share the same 1M unified context window, built-in tools, and per-token pricing. The main difference is how many thinking tokens each model spends per turn: * **Gemini 4 Carbon (`gemini-4-carbon`):** Built for tasks that push the limits of reasoning depth. Carbon spends more thinking tokens per turn to explore thoroughly and verify its work, which increases per-turn token use and latency compared to Argon. Use it for complex root-cause debugging, architectural design, dense multimodal synthesis, scientific proofs, and security auditing. * **Gemini 4 Argon (`gemini-4-argon`):** Our efficient Gemini 4 frontier reasoning model, ideal for most advanced software engineering and knowledge work tasks. It delivers Gemini 4 intelligence with faster responses and lower token spend per turn compared to Carbon on interactive coding, day-to-day feature work, and fast production loops. For more guidance on model selection, see [Latest Gemini models](/docs/latest-model#compare-models). ## Understanding thinking levels {% id=&quot;understanding-thinking-levels&quot; %} The [thinking level](/docs/thinking) is your main control over quality, latency, and token use in Gemini 4 Carbon: | Thinking level | Token use | When to use | | :--- | :--- | :--- | | `low` | Fewest tokens, lowest latency | Simpler tasks and cost-sensitive work. Also works for analysis and writing tasks that need light thinking. Quality can drop on hard tasks. | | `medium` (default) | Balanced | Recommended for most tasks, including complex code and agentic use cases. | | `high` | Most tokens, slowest first token | Complex reasoning, hard math and science, and the most difficult code or agent tasks. Pairs well with long decode for long outputs. | Run your evaluations at all three levels, then pick the lowest level that meets your quality bar. The response stops once thinking plus output hits `max_output_tokens`, so set it high enough to leave room for the final answer. * **Generate past 64K tokens with background execution:** Standard synchronous responses stop at 65,536 tokens. To generate longer responses, set `background=True` and raise `max_output_tokens` above 65,536 (up to the unified 1M-token context window, minus your input tokens). Our servers generate the response in 64K-token continuation hops for you. Each hop adds a `model_output` step to `interaction.steps`, so join the text across all `model_output` steps when the interaction finishes. {% tabs %} {% tab label=&quot;Python&quot; %} ```python import time from google import genai client = genai.Client() interaction = client.interactions.create( model=&quot;gemini-4-carbon&quot;, input=&quot;Write a complete, rigorous proof of the prime number theorem.&quot;, background=True, generation_config={ &quot;max_output_tokens&quot;: 262144, &quot;thinking_level&quot;: &quot;high&quot;, }, ) while interaction.status in (&quot;in_progress&quot;, &quot;queued&quot;): time.sleep(5) interaction = client.interactions.get(id=interaction.id) # Each hop adds a model_output step, so join the text of all of them. text = &quot;&quot;.join( content.text for step in interaction.steps if step.type == &quot;model_output&quot; for content in step.content if content.type == &quot;text&quot; ) print(text) print(&quot;Status:&quot;, interaction.status) print(&quot;Usage:&quot;, interaction.usage) ``` {% /tab %} {% tab label=&quot;JavaScript&quot; %} ```javascript import { GoogleGenAI } from &quot;@google/genai&quot;; const client = new GoogleGenAI({}); let interaction = await client.interactions.create({ model: &quot;gemini-4-carbon&quot;, input: &quot;Write a complete, rigorous proof of the prime number theorem.&quot;, background: true, generation_config: { max_output_tokens: 262144, thinking_level: &quot;high&quot;, }, }); while (interaction.status === &quot;in_progress&quot; || interaction.status === &quot;queued&quot;) { await new Promise((resolve) =&gt; setTimeout(resolve, 5000)); interaction = await client.interactions.get(interaction.id); } // Each hop adds a model_output step, so join the text of all of them. const text = interaction.steps .filter((step) =&gt; step.type === &quot;model_output&quot;) .flatMap((step) =&gt; step.content ?? []) .filter((content) =&gt; content.type === &quot;text&quot;) .map((content) =&gt; content.text) .join(&quot;&quot;); console.log(text); console.log(&quot;Status:&quot;, interaction.status); console.log(&quot;Usage:&quot;, interaction.usage); ``` {% /tab %} {% tab label=&quot;REST&quot; %} ```bash ID=$(curl -s -X POST &quot;https://generativelanguage.googleapis.com/v1beta/interactions&quot; \ -H &quot;x-goog-api-key: $GEMINI_API_KEY&quot; \ -H &quot;Content-Type: application/json&quot; \ -d &#39;{ &quot;model&quot;: &quot;gemini-4-carbon&quot;, &quot;input&quot;: &quot;Write a complete, rigorous proof of the prime number theorem.&quot;, &quot;background&quot;: true, &quot;generation_config&quot;: { &quot;max_output_tokens&quot;: 262144, &quot;thinking_level&quot;: &quot;high&quot; } }&#39; | jq -r &#39;.id&#39;) while true; do RESP=$(curl -s &quot;https://generativelanguage.googleapis.com/v1beta/interactions/$ID&quot; \ -H &quot;x-goog-api-key: $GEMINI_API_KEY&quot;) STATUS=$(echo &quot;$RESP&quot; | jq -r &#39;.status&#39;) if [[ &quot;$STATUS&quot; != &quot;in_progress&quot; && &quot;$STATUS&quot; != &quot;queued&quot; ]]; then echo &quot;$RESP&quot; | jq -r &#39;[.steps[]? | select(.type == &quot;model_output&quot;) | .content[]? | select(.type == &quot;text&quot;) | .text] | join(&quot;&quot;)&#39; break fi sleep 5 done ``` {% /tab %} {% /tabs %} {% callout type=&quot;note&quot; %} If you set `background: true` without defining `max_output_tokens`, the server stops after 64K tokens. {% /callout %} Background execution is the recommended way to run long decode. It runs the continuation loop server-side until the model finishes or reaches `max_output_tokens`. If you need finer-grained control over retries, backoff, and error handling (or don&#39;t want your interactions stored), you can use client-side continuation in the [Interactions API](/docs/long-decode#client-side-continuation) or the [GenerateContent API](/docs/long-decode?generate-content=true). For streaming, reconnection, token counting, and when to use long decode, see the [long decode guide](/docs/long-decode). ### Setting output token limits {% id=&quot;setting-output-token-limits&quot; %} `max_output_tokens` sets the maximum combined thinking and output tokens for a response. Set it high enough that thinking doesn&#39;t cut the answer short, and low enough to limit spend when a hard prompt uses all of it. Use these values as a starting point: * **Standard tasks:** Keep the default of 65,536 or don&#39;t set any value. * **Existing apps with a limit lower than 32K:** Raise `max_output_tokens` to at least 32,768. Gemini 4 Carbon can spend more of the limit on thinking than earlier models. To use fewer tokens, lower the thinking level instead. * **Complex reasoning and coding:** Set `background: true` and set `max_output_tokens` to 131,072 or 262,144, up to 1,048,576 minus your input tokens. ## Gemini 4 Carbon in Managed Agents {% id=&quot;managed-agents&quot; %} The [Antigravity agent](/docs/antigravity-agent) in Gemini Managed Agents supports Gemini 4 Carbon. If you use a coding agent that supports skills (like Antigravity), install the [gemini-api-dev skill](/docs/coding-agents#gemini-api-dev) and run: ```none /gemini-api-dev migrate my app to Gemini 4 Carbon ``` {% /callout %} ### Migrate from Gemini 4 Argon {% id=&quot;migrate-from-gemini-4-argon&quot; %} If you already run `gemini-4-argon`, upgrading to `gemini-4-carbon` requires no request schema changes: * **Update model ID:** Change your model string from `gemini-4-argon` to `gemini-4-carbon`. * **Account for longer thinking:** Carbon spends more thinking tokens per turn than Argon on complex tasks. Keep `thinking_level` at `medium` (default) unless a workload needs `high`, and make sure your `max_output_tokens` and HTTP timeouts allow for longer reasoning passes. * **Keep Argon where speed matters:** Retain [`gemini-4-argon`](/docs/whats-new-gemini-4-argon) when you want faster responses and lower token spend per turn compared to Carbon on interactive coding, day-to-day feature work, and fast production loops. ### Migrate from Gemini 3 and earlier {% id=&quot;migrate-to-gemini-4-carbon&quot; %} * **Update model ID:** Change your target model string to `gemini-4-carbon`. * **Review `max_output_tokens`:** If you set it explicitly today, consider raising it. We recommend at least 32,768, since Gemini 4 Carbon can spend more of the limit on thinking. * **Configure thinking level:** Choose `low`, `medium` (default), or `high`, and test your workload at all three. * **Move off explicit context caching:** Explicit caching (`cachedContents` / `caches.create`) is not supported on Gemini 4 Carbon. Remove calls that create or reference `cached_content` from your requests. [Implicit caching](/docs/caching) is enabled by default for prompts of at least 4,096 tokens and discounts cached input tokens by 95% on cache hits. * **Remove sampling parameters:** Remove `temperature`, `top_p`, and `top_k` from your requests. If provided, they are ignored. * **Use background execution for long outputs:** For tasks that need more than 64K tokens, set `background` to true and `max_output_tokens` greater than 65,536. * **Increase client timeouts:** Hard prompts can take several minutes. Use background execution, or set HTTP client timeouts to at least 15 minutes. * **Keep conversation state on the server:** Use `previous_interaction_id` for multi-turn and function calling conversations. * **Review your cost estimates:** Every token the model processes is billed, including internal tool system instructions and function declarations when using grounding (see [Pricing](/docs/whats-new-gemini-4-carbon#pricing)). ## Pricing {% id=&quot;pricing&quot; %} Gemini 4 Carbon is available at introductory pricing through November 30, 2026: * **Input tokens:** $2.00 per 1M tokens ($4.00 starting December 1, 2026) * **Cached input tokens:** Implicit caching discounts cached input by 95%, to $0.10 per 1M tokens ($0.20 starting December 1, 2026). * **Output tokens, including thinking tokens:** $10.00 per 1M tokens ($20.00 starting December 1, 2026) Every token the model processes is counted and billed, including thinking tokens and internal tool system instructions and function declarations when using grounding. Grounding with Google Search also remains billed per query. Gemini 4 Carbon is not available on the Free tier.
